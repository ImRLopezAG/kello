## Choose a result lifecycle

| Need                    | Generated native option | Result                                             |
| ----------------------- | ----------------------- | -------------------------------------------------- |
| One finite page         | `queryOptions`          | `rows`, boundary cursors, optional decimal `count` |
| Accumulate finite pages | `infiniteOptions`       | TanStack pages of finite responses                 |

Generated search provides finite pages. A separate declared Neon `.live()` SELECT can use validated page inputs; it does not inherit nested search mapping, counts or encrypted search cursor semantics.

## Client-only and suspense

<Snippet code={clients} />

These components require `KelloProviderWithAuth` and a `QueryClientProvider` above them. Authentication comes from the provider's auth hook; client-only rendering requires no frontend session server. `SuspenseTasks` needs a React Suspense boundary plus an error boundary. Search calls use ordinary TanStack hooks.

`MoreTasks` starts with `initialPageParam: null`. After each response, `getNextPageParam` extracts `nextCursor`. TanStack automatically passes that value to oRPC's `input(cursor)` callback, which builds the next request by adding the cursor to the unchanged selection. The callback maps a page parameter into the contract's input; no component state stores or advances the cursor. oRPC requires this mapping because other contracts can paginate by offset, page number or a nested field. A returned null cursor terminates traversal.

Backward traversal uses `direction: "backward"` and `previousCursor`; without a cursor it starts at the dataset tail. A separate child search contract handles independently paginated children: nested `limit` is a bounded preview, not a child cursor.

## Understand concurrent writes

Each finite page has one database snapshot. Across separate requests, new rows before the boundary are not backfilled, deleted rows are skipped, and sort-key updates may move a row across the boundary. A boundary row may be deleted without invalidating its cursor. Refresh restarts traversal; count describes the current request's authorized snapshot.

Call this separately for every request. Its QueryClient and connection are request-scoped; one user's cache cannot be reused for another. Supply the token from your existing auth provider and the request abort signal. `queryClient.query(...)` is the native finite operation. The returned dehydration payload carries the finite selected result for hydration.

Neon live queries are browser subscriptions and are not issued during SSR. A Next.js or TanStack Start application can prefetch a finite contract, or render a client-only live component when no finite bootstrap is needed. SSR itself does not require hosting authentication in the frontend application.

## Cache controls and projection safety

Default keys distinguish selection, ordered sorting priority and verified auth scope. Explicit custom keys are caller-owned: reusing one key for incompatible projections can mix cache values. Avoid broad cache writes or custom query functions that violate the declared result shape.

Search-specific runtime checks preserve the native option surface while validating supplied initial and placeholder data and shadowing inherited QueryClient data defaults. A previous title-only page cannot satisfy a new done-only selection. Compatible structural extra fields in initial data remain allowed; missing selected fields and wrong scalars are rejected. Ordinary procedures retain native behavior. These guards are not a replacement for authorizing and validating server responses.
