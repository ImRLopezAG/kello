## Declare the contract

Every procedure has a contract under `kello/contracts/`. A file owns its route prefix: `contracts/tasks.ts` declares `tasks.*`. Use `defineContract({...})` or its callback form when you need generated validators. Native oRPC contracts carry input/output schemas, errors and metadata. Output schemas are required; input is optional.

<Snippet code={contractsSource} />

Zod and Valibot both work through Standard Schema. The contract determines client input and output types, and validates values at runtime. Declare live SQL with `.live()`; use `eventIterator(...)` for ordinary HTTP streaming. Finite contracts stay finite.

## Configure the application

`app.config.ts` defines server environment validation and named native builders. Its `rpc` callback can return `os` and middleware-refined builders such as `auth`. Declare shared errors on a shared contract base before using them in router-wide middleware.

<Snippet code={applicationSource} />

Add `env: { STRIPE_SECRET_KEY: z.string() }` or the equivalent Valibot schema to validate server variables. Handlers receive the parsed values through `context.env`. Generation never reads secrets; deployment validates custom values, and Neon Functions startup validates its full environment including provider-injected values. Mount reusable [components](/authoring/components) explicitly with `app.use`; [SDK services](/authoring/sdk-services) can be mounted without schemas or contracts.

## Implement the router

Import named builders from `kello/_generated/rpc`. Default-export native routers below `kello/functions/`; server-only routers and their contracts belong below `kello/internal/` and `kello/contracts/internal/`. Internal routes are absent from the generated public client and public transports.

Call current-scope private operations through `context.internal`, and mounted backend exports through `context.components.<mount>.rpc`. Their contract types and the outer invocation's transaction authority are preserved. A component uses its own generated builders and private registry.

<Snippet code={functionsSource} />

Handlers receive typed `db`, `tables`, `validators`, `identity`, `env`, storage and scheduler capabilities. Generation binds schema and relations once. Use native `.handler`, `.effect`, `.use` and router composition. Generation rejects missing implementations, extra routes and implementations that do not match their declared contracts.

## Live SQL procedures

On a Realtime-enabled Neon branch, declare a live read in the same contract and function folders. The contract describes the rows; the function returns the Drizzle SELECT that Neon will run.

```ts title="kello/contracts/tasks.ts"
import { defineContract, oc } from "kello/contract";
import * as v from "valibot";

export default defineContract({
  list: oc
    .input(
      v.strictObject({
        projectId: v.string(),
        after: v.optional(v.string()),
        limit: v.pipe(v.number(), v.integer(), v.minValue(1), v.maxValue(100)),
      }),
    )
    .output(v.array(v.strictObject({ id: v.string(), title: v.string() })))
    .live(),
});
```

```ts title="kello/functions/tasks.ts"
import { and, asc, eq, gt, sql } from "drizzle-orm";
import { os } from "../_generated/rpc";

export default os.tasks.router({
  list: os.tasks.list.live(({ context, input, errors }) => {
    if (!context.identity) throw errors.UNAUTHORIZED();
    const tasks = context.tables.tasks;
    return context.db
      .select({ id: sql<string>`${tasks._id}`.as("id"), title: tasks.title })
      .from(tasks)
      .where(
        and(
          eq(tasks.projectId, input.projectId),
          eq(tasks.ownerId, context.identity.subject),
          eq(tasks.ownerIssuer, context.identity.issuer),
          input.after ? gt(tasks._id, input.after) : undefined,
        ),
      )
      .orderBy(asc(tasks._id))
      .limit(input.limit);
  }),
});
```

Return the query **without `await` or an `async` callback**: awaiting a Drizzle builder executes it. Use the normal `.use()` middleware for asynchronous validation or permission checks before returning the query. Include all row permissions in SQL as well, including membership joins when access can change. Neon does not inherit transaction-local identity settings, RLS, or application middleware.

Output keys must match the selected SQL column names. When renaming a column, use an explicit SQL alias as shown for `_id` above; Neon does not run Drizzle's result mapper.

Pagination is ordinary validated input. This example uses an ordered ID cursor; changing `after` or `limit` opens a new subscription for that page. It does not accumulate pages or create an opaque pagination token. Choose a total ordering and matching cursor predicate for your query.

Configure the server once in `app.config.ts`:

```ts
defineApplication({
  env: {
    NEON_REALTIME_SECRET: v.string(),
    NEON_DATABASE: v.string(),
    DEPLOYMENT_ID: v.string(),
  },
  liveQueries: ({ env }) => ({
    secret: env.NEON_REALTIME_SECRET,
    database: env.NEON_DATABASE,
    deployment: env.DEPLOYMENT_ID,
    resolveLogin: async ({ verified, credential, signal }) => {
      // Use your real server session store. Never derive a generation from a subject or client label.
      return sessionStore.resolveVerifiedLogin({ verified, credential, signal });
    },
  }),
  rpc: ({ os }) => ({ os }),
});
```

The resolver returns a `TrustedLogin` matching the verified issuer, subject and tenant, with a stable session-store generation and expiry. Credentials stay server-only. Missing login authority refuses live reads. Verified sessions must remain valid for the SDK's signed 60-second capability lifetime. Renewal reruns native input validation and middleware with the current credential; SQL permission predicates govern changes between renewals.

Generation adds a React entry beside the ordinary client:

```tsx
import { createClient } from "./kello/_generated/react";
import { createKelloReact } from "kello/react";

export const { KelloProvider, useKello } = createKelloReact((options) =>
  createClient({ ...options, realtimeUrl: "https://your-branch-realtime-endpoint" }),
);

function TaskList({ projectId, after }: { projectId: string; after?: string }) {
  const { api } = useKello();
  const tasks = api.tasks.list.useLiveQuery({ projectId, limit: 20, ...(after ? { after } : {}) });
  if (tasks.isPending) return <p>Connecting…</p>;
  if (tasks.failed) return <button onClick={tasks.refetch}>Retry live query</button>;
  return (
    <section>
      {tasks.status !== "live" && <p>Reconnecting; showing the last installed rows.</p>}
      <ul>
        {tasks.data?.map((task) => (
          <li key={task.id}>{task.title}</li>
        ))}
      </ul>
    </section>
  );
}
```

The generated connection owns renewal and disposal through the existing provider's login/logout lifecycle. `status` exposes connecting, live, stale, closed and error states. `refetch()` replaces the subscription; `confirm(receipt, timeoutMs)` waits for the current subscription's installed transaction progress. A timeout or disconnect means **unknown**, not a rolled-back mutation. Existing `runNeonMutation` receipts remain the opt-in write contract.

This first version accepts flat scalar SELECTs and representable Valibot row-array outputs. Unsupported nested projections, custom decoders and unrepresentable output refinements fail closed. Input schemas retain normal Standard Schema validation. Live capability results are excluded from ordinary Query utilities and SSR dehydration; SSR does not issue a subscription. Ordinary procedures and live issuance use authenticated HTTP. Neon’s SDK owns live delivery; no custom ticket/WebSocket transport remains.

## Transactions and operation intent

The generated client forwards native oRPC option intent. Query, infinite and streamed options select read-only repeatable-read transactions. Declared live reads issue an authorized query through HTTP. Mutation options and direct calls select serializable write transactions. Explicit iterator contracts always use read-only authority, including direct calls. Handlers run once per request; Kello does not automatically retry application code after transaction conflicts.

Client intent is untrusted and never grants permission. Authorization runs for every call, and PostgreSQL rejects writes in read-only transactions. JavaScript can still call external services; neither operation intent nor the database makes those effects safe to repeat. An ordinary stream runs for its request lifetime; it is not automatically reevaluated.

For application handlers, the authorization callback receives `databasePolicy: "automatic"`, regardless of the client's selected options. Authorize from the verified identity, route and owned data; do not use transaction intent to relax access checks.

Output validation and serialization finish before finite database writes commit. Declare native OpenAPI metadata on contracts and set `openapi: true` in `kello.config.ts` to expose the validated REST graph. A REST request does not carry TanStack option intent; use `.live()` for live SQL or explicit iterator contracts for ordinary streaming and enforce authorization independently of HTTP method.

## IDs and authorization

Use `validators.id("tasks")` or `schema.id("tasks")` to validate UUID syntax and infer `Id<"tasks">`. IDs do not prove table membership, existence or access. Check the row and ownership inside the transaction; schema references supply database foreign keys. Filter by verified issuer and subject plus your tenant policy.

## Effect and invocation lifetime

`.effect(function* (...) { ... })` uses the shared Effect runtime. Generated `Database`, `Tables` and `Validators` services preserve project types; `Invocation`, `Diagnostics`, `Storage` and `RpcSchedulerService` expose invocation capabilities. Read-only calls cannot schedule writes or create storage intents.

Use `Effect.tryPromise` for fallible Promise operations. `Effect.promise` turns a rejected Promise into a defect, which Kello redacts. Declare public errors on the contract. Await database, scheduler and storage operations: invocation-owned work drains before completion, and escaped capabilities reject after the invocation ends. Storage commits independently from application SQL.

## Replay

Explicit write idempotency keys identify one logical invocation. Authorization runs again before replay. Reusing a key with different arguments conflicts; an incompatible saved protocol returns `RPC_VERSION_MISMATCH`. Retention is bounded, and external providers need their own idempotency guarantees. See [native client options](/authoring/subscriptions) for retry and cache ownership.

## Choose the client operation

| Intent                           | Native client call                                            | Handler constraint                                  |
| -------------------------------- | ------------------------------------------------------------- | --------------------------------------------------- |
| Read one finite result           | `rpc.tasks.greeting.queryOptions({ input: { name: "Ada" } })` | No database writes                                  |
| Create a task                    | `rpc.tasks.create.mutationOptions()`                          | Authorize and write within the invocation           |
| Receive current and future tasks | `api.tasks.list.useLiveQuery()`                               | Explicit live SELECT with SQL permission predicates |

The same generated builders implement all three. You do not add a separate `query()` or `mutation()` wrapper on the server. The client option selects execution intent, while the contract and authorization policy remain the server's authority.

For an expected failure, declare an error on the contract and throw `errors.NAME()` from the handler. Do not expose database messages or provider secrets through arbitrary error strings. See [Effect](/integrations/effect) for the corresponding typed failure form.
