## Connect once per login

Follow [React clients](/clients/react) and import the generated React entry to receive both native `rpc` options and the typed live `api`. The provider verifies credentials, replaces connections when the login changes, and disposes private state on logout. Manually managed connections need the same ownership: clear their QueryClient and dispose the connection before switching identities. Never put tokens in query keys.

## Declare live SQL explicitly

Declare a row-array output with `.live()` in `kello/contracts/`, then implement it with a synchronous `.live(({ context, input }) => selectBuilder)` in `kello/functions/`. See the complete [live SQL example](/authoring/functions#live-sql-procedures).

The handler returns a typed Drizzle SELECT without executing it. Use explicit aliases and supported flat scalar projections. Include tenant, issuer, subject and current membership predicates in SQL. Middleware runs when issuing or renewing; it is not executed by the Neon proxy for every changed row. A trusted server login resolver supplies the actual session generation and expiry.

```tsx
const { api, rpc } = useKello();
const tasks = api.tasks.list.useLiveQuery({ projectId });
const update = useMutation(rpc.tasks.setDone.mutationOptions());
```

This assumes the task contracts from `packages/examples/tasks`. Use `tasks.isPending` for initial loading, `tasks.failed` for issuance failures, and `tasks.status` for connecting/live/stale/closed/error. `tasks.refetch()` replaces the subscription. The official Neon SDK owns delivery and renewal; Kello does not fall back to polling.

Changing input or login creates a different subscription. Keep live rows out of ordinary TanStack Query hydration and do not use a cached finite response as evidence of installed transaction progress. SSR can prefetch a separate finite contract.

## Optimistic updates and retries

Render pending mutation variables over the last installed rows, or use TanStack cache edits for ordinary finite queries. Kello does not prove arbitrary Query-cache provenance or reconcile overlapping application intents automatically.

For a write explicitly returning a scoped `runNeonMutation` receipt, `await tasks.confirm(receipt, timeoutMs)` reports `confirmed` only after that subscription has installed the transaction's progress. Confirmation does not mean the changed row matches the query or that its value remains unchanged. Timeout, disconnection, disposal and scope mismatch mean `unknown`, not rollback. An ordinary mutation result has no such receipt by default.

Mutations do not retry automatically. Reuse one idempotency key only when retrying the same logical write; a new write needs a new key. External effects need their own idempotency policy. Guard callbacks against login changes.

## Ordinary streaming is separate

User-authored `eventIterator` procedures stream through HTTP with cancellation and iterator finalization. They run for that invocation; they are not automatically reevaluated and do not acquire Neon confirmation semantics. There is no Kello ticket or application WebSocket transport.

## Alpha migration

Remove `context.live`, generated search `watch`/`liveSearch`, polling/notify configuration and custom socket clients. Use `.live()` for a supported SELECT or keep a finite procedure and refetch explicitly. The normal metadata migration removes framework revision objects while preserving application data and applied migration hashes. No legacy backend compatibility mode is retained.
