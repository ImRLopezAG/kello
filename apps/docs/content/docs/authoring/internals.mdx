## Declare a private contract

Put private contracts in `kello/contracts/internal/` and their routers in `kello/internal/`. Use the same contract rules as public procedures: output schemas are required, input schemas are needed when accepting arguments, and expected public errors are declared on the contract. Generated builders preserve these types.

A handler calls `context.internal.<file>.<procedure>(input)`. A component gets its own `context.internal`, not the parent's private registry. Internal contracts do not appear in browser clients, OpenAPI, or public HTTP dispatch.

## Call across components intentionally

`app.use(component)` returns a mount reference. Its exported backend procedures become available through `context.components.<mount>.rpc`; its services are under the corresponding services capability. Siblings are not automatically dependencies: bind another mount explicitly with `dependencies`.

Nested calls share the outer transaction and verified identity. A read-only caller cannot upgrade to write authority by invoking another component. An inner failure prevents the outer transaction from committing even if application code catches it. Await nested operations so invocation-owned work does not escape its lifetime.

## Choose a procedure or a service

Use an internal procedure for a validated input/output operation that participates in Kello execution. Use a component service for an initialized SDK or in-process capability. A service is not automatically a public RPC and does not need a wrapper for every SDK method.

Use the [scheduler](/authoring/jobs) when work must survive the current request. Pass the internal procedure object to `runAfter` or `runAt`; do not construct procedure names or source versions manually.
