## Cloud-only backend

Application handlers, jobs and cron schedules execute in Neon Functions. Local tooling edits source, generates bindings, builds deployment archives and watches a linked preview target. There is no local backend server or PostgreSQL fallback.

Ordinary RPC and user-authored iterators use HTTP. Declared `.live()` functions issue authorized SELECTs over HTTP and receive updates through the official Neon SDK. The removed polling/LISTEN coordinator, snapshot engine and custom application WebSocket transport have no supported mode.

## Live-query limits

The current wrapper permits 100 owned subscriptions per client and 32 pending confirmation waiters per subscription. These are admission caps, not a throughput or whole-graph memory guarantee. Supported queries use explicit flat scalar projections and validated output schemas; unsupported mapping and refinements fail closed. Nested relational search, automatic counts and encrypted finite-search cursors are not converted to live queries.

Row permissions must be present in SQL. Transaction-local identity settings and RLS do not transfer to the Realtime proxy. Issuance and renewal require verified credentials, trusted login generation and sufficient remaining expiry. Dispose the connection on logout. Timeout, disconnection or disposal leaves write confirmation unknown.

Earlier revision-engine latency/load measurements describe a removed implementation and do not establish a Neon performance SLA. Actual-provider evidence covers selected commit/retry/replay, authorization, renewal and delivery-order cases; it does not prove every projection, provider quota, reconnect duration or long-running retention bound. Current cloud-only deployment and browser acceptance must be checked at the tested revision.

## Preserved data and jobs

Migration 29 retires framework revision triggers/function/table and connection tickets through the ordinary migration path. Applied versions 1–28 remain immutable. User tables, unrelated triggers and cloud job data remain. There is no old-deployment drain gate for this breaking alpha.

Database retirement retains its activation, job and client-session checks and historical artifacts. A database retirement receipt does not prove that every remote process or external effect has stopped.

## Package status

Kello is an experimental MIT-licensed alpha. Install the published alpha tag deliberately; final package, exact-revision CI and release checks remain separate from individual source or native test results.

Deployment tooling needs Vite+ in the application's devDependencies. The uploaded function bundle does not need the authoring toolchain. `pg` remains for Neon SQL and migrations, `libpg-query` for migration analysis, and `fflate` for ZIP archives. Removing direct esbuild/NFT dependencies does not establish their absence from the retained official Neon CLI's transitive graph.
