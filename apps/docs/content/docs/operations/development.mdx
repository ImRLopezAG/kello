## Select a preview target

Run `kello login`, then `kello link --project-id <id> --branch <branch-id>` for an unprotected, nondefault PostgreSQL 18 branch. `kello dev` requires the saved link and the preview deployment target to identify the same project and branch. Production targets are refused.

Normal linked projects discover deployment credentials and settings. Explicit overrides belong in `kello.config.ts`: `deployment.environment` must be `"preview"`, and `provider.targets.preview` selects that branch. Optional `development` settings select `databaseName`, `migrationRole`, `runtimeRole` and `debounceMs` (75 milliseconds by default). They do not start a local database or server.

Generate migration artifacts with `kello migrations generate --name <name>` before deploying schema changes. Development uses the ordinary release pipeline and its migration admission rules. Keep applied migration history intact.

## Watch and deploy

Run `kello dev --cwd <project>`. Each changed source version generates bindings and deploys through the existing Neon release pipeline to the same preview branch. Updates run serially; newer saves cancel superseded work and coalesce into one successor. Publication events that do not change the source version do not redeploy.

The command prints the remote service URL when the release succeeds. A failed build or deployment leaves the last successful remote release active; save a corrected edit to retry. Target or declaration failure during initial setup exits before watching. `--development <file>` selects a contained release declaration, using the same format as `kello deploy`.

`--json` emits `watching`, `ready` and `stopped` lifecycle events. Update failures report `DEVELOPMENT_UPDATE_FAILED` on stderr. SIGINT and SIGTERM stop watching, cancel pending work, and await an already-started release's cleanup. The shared preview branch and its last release remain available after exit.

Application handlers, jobs and cron schedules execute in Neon. You can run a frontend, code generation and file watching locally. Ordinary RPC and user-authored async iterators use HTTP; declared `.live()` queries use Neon Realtime.

The alpha removes local server/runtime/synchronization APIs, local port and connection limits, local activation/storage declarations, `kello dev quarantine`, and dev's `--diagnostics`, `--diagnostics-file` and `--telemetry` attachment flags. Release clone/preserve quarantine remains part of deployment.

## Programmatic diagnostics

Use the public server-side `kello/tooling` entrypoint under Bun or Node 24. At least one output or telemetry sink is required, and only one session may be active per JavaScript realm, including duplicate package instances. A competing start rejects with `DIAGNOSTICS_ALREADY_ACTIVE`. The API observes its caller's process; it is not a browser API or a remote attach command.

```ts
import { open } from "node:fs/promises";
import { startDiagnostics } from "kello/tooling";
import type { DiagnosticsOptions, DiagnosticsSession } from "kello/tooling";

const file = await open("./diagnostics.jsonl", "wx", 0o600);
const options: DiagnosticsOptions = {
  output: {
    format: "jsonl",
    async write(chunk, signal) {
      signal.throwIfAborted();
      await file.writeFile(chunk);
      signal.throwIfAborted();
    },
  },
};
let session: DiagnosticsSession | undefined;
try {
  session = await startDiagnostics(options);
  // Run your server-side workload here while the session is active.
  console.error(session.snapshot());
} finally {
  await session?.stop();
  await file.close(); // Caller-owned I/O cleanup can outlast session.stop().
}
```

For programmatic export, replace or supplement `output` with `telemetry: { protocol: "otlp-http-json", endpoint: "http://127.0.0.1:4318/v1/metrics" }`, optionally supplying `bearerToken`. Programmatic configuration uses these explicit options, not CLI environment discovery. `DiagnosticsRecord`, `DiagnosticsStats`, `DiagnosticsRuntimeEvent` and `DiagnosticsDeploymentEvent` are also public type exports.

Writers receive `(chunk: string, signal: AbortSignal)` and return `void` or `Promise<void>`. Return promptly and cooperate with cancellation before deferred writes. The example checks cancellation around an OS write but cannot undo bytes already submitted. `stop()` is idempotent and prevents new calls synchronously; pending caller-owned work can outlive bounded adapter cleanup. Use `snapshot()` for final loss statistics because stop writes no final local record.

Returned promises must allow standard settlement observers to attach. Promise subclasses, constructor getters and reentrancy are supported when observation remains possible. Deliberately sabotaged constructor/species/then behavior that prevents observation is unsupported; a later unhandled rejection remains the caller's risk. The adapter does not mutate promises or install global exception/rejection handlers.

## Jobs, storage and components

Preview releases execute cloud jobs and crons and use branch-bound storage. Configure provider resources through the deployment workflow; development does not emulate them.

Import component setup and mount it with `app.use(component)`. Generate migration artifacts for schema changes before saving/deploying the release. Removing a mount does not authorize dropping its persisted data. Review destructive changes through the migration workflow.

Without a running watcher, editing source does not publish a release. Use `kello generate` to refresh bindings and `kello deploy` to publish. A local frontend connects to the remote preview service.
